## 1. 引言

### 1.1 目的

本文档用于定义 DSTServerTool 的版本化软件需求，统一产品、开发、测试对当前首版与后续版本范围的理解。

### 1.2 范围

DSTServerTool 是一个面向多平台 DST 服务器管理员的桌面工具。系统以 Tauri 为桌面容器，前端采用 Vue + Vite + Reka UI，提供本地服务器准备、模组更新、默认存档准备、Token 配置、服务端启动与日志查看能力。

**首版 (0.0.0) 聚焦**: Windows 平台本地服务器管理。

**后续版本目标**: 支持 Windows/macOS 图形界面应用、Linux 远程管理、多服务器集群管理、云端部署集成等高级功能。

### 1.3 术语与缩略词

| 术语 | 定义 |
|------|------|
| DST | Dont Starve Together |
| Tauri | 桌面应用容器框架 |
| Cluster | DST 服务器存档/配置目录 |
| Token | DST 服务器认证所需令牌 |
| Feature | 一组面向用户价值的功能集合 |

## 2. 总体描述

### 2.1 产品视角

DSTServerTool 位于本地管理员、Steam 安装目录、DST Dedicated Server 目录和 Cluster 存档目录之间，负责把已有脚本能力和本地文件操作组织为桌面 UI 流程。

### 2.2 用户类型

| 用户类型 | 描述 |
|----------|------|
| 新手服主 | 需要低门槛完成首次本地服务器准备 |
| 服务器管理员 | 需要频繁更新模组、检查日志、调整路径 |
| 排障人员 | 需要查看启动输出和失败原因 |

### 2.3 运行环境

| 类型 | 要求 |
|------|------|
| 操作系统 | Windows 10/11 64 位 (首版) / macOS 10.15+ / Linux (Ubuntu 20.04+, Debian 11+) |
| 桌面容器 | Tauri 2.x |
| 前端 | Vue 3 + Vite + Reka UI |
| 本地能力 | Rust（Tauri Command）+ Python 3.x 兼容层 |
| 远程管理 | SSH/SFTP 连接 (Linux 服务器) |

- 前端已迁移到 Vue 3 + Vite + shadcn-vue，并已有可折叠基础壳层。
- Python 模组更新核心已可执行。

## 3. 功能需求

## 3.1 `0.0.0` 版本需求

### Feature: 环境检测与路径确认

#### FR-PATH-001 自动检测已安装目录

- 目标版本: `0.0.0`
- 描述: 系统必须自动检测本机的 Steam 根目录、DST 游戏目录和 DST Dedicated Server 目录。
- 成功标准: 用户首次进入初始化页面时，系统能返回已检测到的路径或明确说明未检测到。

#### FR-PATH-002 手动修正与再次检测

- 目标版本: `0.0.0`
- 描述: 当自动检测失败或结果不正确时，系统必须允许用户手动输入或重新选择路径。
- 成功标准: 用户可修改任一路径并立即重新验证。

#### FR-PATH-003 路径持久化

- 目标版本: `0.0.0`
- 描述: 系统必须保存已确认路径，并在下次启动时恢复。
- 成功标准: 应用重启后仍能加载最近一次有效路径配置。

### Feature: 模组自动更新

#### FR-MOD-001 服务器模组扫描

- 目标版本: `0.0.0`
- 描述: 系统必须扫描服务器 `mods` 目录中的 `workshop-*` 模组。
- 成功标准: 系统只识别合法模组目录，并生成待处理列表。

#### FR-MOD-002 来源模组匹配与优选

- 目标版本: `0.0.0`
- 描述: 系统必须在 Workshop 目录和游戏目录中查找对应来源模组，并按更新时间选择最优来源。
- 成功标准: 每个服务器模组都得到 `可更新 / 无变化 / 缺失` 中的一种明确判定。

#### FR-MOD-003 安全更新与回滚

- 目标版本: `0.0.0`
- 描述: 系统必须仅在来源更晚时替换服务器模组，并在失败时回滚。
- 成功标准: 任一模组更新失败后，不得留下半更新目录。

#### FR-MOD-004 结果展示

- 目标版本: `0.0.0`
- 描述: 系统必须展示逐项处理状态、原因、来源路径和摘要统计。
- 成功标准: 用户能区分 `updated`、`unchanged`、`missing`、`failed`。

### Feature: 默认存档创建与复制

#### FR-SAVE-001 创建默认 Cluster

- 目标版本: `0.0.0`
- 描述: 系统必须支持创建一个可用于后续启动的默认 Cluster 目录结构。
- 成功标准: 目标路径下生成所需基础目录和最小配置文件集合。

#### FR-SAVE-002 复制默认存档基线

- 目标版本: `0.0.0`
- 描述: 系统必须支持将默认模板或已有基础存档复制到目标 Cluster。
- 成功标准: 用户完成复制后，可看到明确的目标目录和结果状态。

#### FR-SAVE-003 写入前校验

- 目标版本: `0.0.0`
- 描述: 系统必须在创建或复制前校验目标路径是否存在、可写且不会无提示覆盖关键内容。
- 成功标准: 无权限、不可写或目标冲突时阻止执行并给出原因。

### Feature: Token 配置指导与启动脚本修改

#### FR-TOKEN-001 Token 获取指导

- 目标版本: `0.0.0`
- 描述: 系统必须提供 Token 获取说明、填写入口和基本格式提示。
- 成功标准: 用户无需离开应用即可知道 Token 应如何获取和填入。

#### FR-TOKEN-002 Token 写入

- 目标版本: `0.0.0`
- 描述: 系统必须将用户确认的 Token 写入对应配置文件或启动所需位置。
- 成功标准: 写入后目标文件中存在可供启动流程使用的 Token 配置。

#### FR-TOKEN-003 启动脚本补齐

- 目标版本: `0.0.0`
- 描述: 系统必须按当前路径和 Token 配置更新启动脚本中的关键参数。
- 成功标准: 生成或修正后的启动脚本处于可执行状态。

### Feature: 服务端后台启动与日志输出

#### FR-RUN-001 后台启动

- 目标版本: `0.0.0`
- 描述: 系统必须能在桌面端触发 DST Dedicated Server 后台启动。
- 成功标准: 启动任务被创建，界面显示启动中状态。

#### FR-RUN-002 实时日志输出

- 目标版本: `0.0.0`
- 描述: 系统必须持续展示启动过程中的标准输出与标准错误。
- 成功标准: 用户能在同一界面连续看到日志滚动更新。

#### FR-RUN-003 运行状态反馈

- 目标版本: `0.0.0`
- 描述: 系统必须展示启动中、运行中、失败、结束等任务状态。
- 成功标准: 任一状态变化都能在 UI 中明确可见。

#### FR-RUN-004 基础停止操作

- 目标版本: `0.0.0`
- 描述: 系统应支持对当前后台运行任务执行基础停止。
- 成功标准: 用户可发起停止，系统记录停止结果。

#### FR-MACOS-001 macOS 原生支持

- 目标版本: `>0.0.0`

#### FR-LINUX-001 SSH 连接管理

- 目标版本: `>0.0.0`
- 描述: 系统应支持通过 SSH 连接远程 Linux 服务器进行管理。
- 成功标准: 用户可配置 SSH 连接信息（主机、端口、用户名、密钥/密码）并保存多个服务器连接。

#### FR-LINUX-002 远程路径检测

- 目标版本: `>0.0.0`
- 描述: 系统应支持在远程 Linux 服务器上检测 DST Dedicated Server 安装路径。
- 成功标准: 用户可通过远程命令查询服务器目录结构并选择目标路径。

#### FR-LINUX-003 远程模组更新

- 目标版本: `>0.0.0`
- 描述: 系统应支持远程执行模组扫描、更新和同步操作。
- 成功标准: 远程模组更新流程与本地操作保持一致的交互体验。

#### FR-LINUX-004 远程日志查看

- 目标版本: `>0.0.0`
- 描述: 系统应支持远程查看服务器启动日志和运行状态。
- 成功标准: 日志通过 SSH 实时流式传输到本地客户端展示。

#### FR-LINUX-005 远程启动/停止

- 目标版本: `>0.0.0`
- 描述: 系统应支持远程启动和停止 DST 服务器进程。
- 成功标准: 用户可在本地客户端触发远程服务器操作并查看执行结果。

### Feature: 多服务器集群管理

#### FR-CLUSTER-001 集群概览

- 目标版本: `>0.0.0`
- 描述: 系统应支持同时管理多个 DST 服务器集群。
- 成功标准: 用户可在单一界面查看所有已添加服务器的状态概览。

#### FR-CLUSTER-002 批量操作

- 目标版本: `>0.0.0`
- 描述: 系统应支持对多个服务器批量执行模组更新等操作。
- 成功标准: 用户可选择多台服务器并行执行相同任务。

### Feature: 云端部署集成

#### FR-CLOUD-001 云服务器快速部署

- 目标版本: `>0.0.0`
- 描述: 系统应支持主流云平台（AWS EC2、阿里云、腾讯云等）快速创建和配置 DST 服务器实例。
- 成功标准: 用户可通过向导流程在云端一键部署 DST 服务器。

#### FR-CLOUD-002 云端远程管理

- 目标版本: `>0.0.0`
- 描述: 系统应集成云服务器远程管理能力，自动建立 SSH 连接。
- 成功标准: 云服务器创建后自动添加到服务器列表并可立即管理。

## 7. 接口需求

### 7.1 UI

- 系统必须提供与 `0.0.0` 五个 Feature 对应的界面入口。
- 系统必须基于 Vue + shadcn-vue 保持统一交互样式。
- 日志界面必须支持空状态、执行中状态和失败状态。

### 7.2 本地命令接口

| 接口 | 用途 |
|------|------|
| `detect_paths` | 自动检测 Steam、DST、Dedicated Server 路径 |
| `validate_paths` | 校验用户修正后的路径 |
| `run_mod_update` | 执行模组更新 |
| `create_default_cluster` | 创建默认存档结构 |
| `copy_default_cluster` | 复制默认模板或已有存档 |
| `write_token_config` | 写入 Token 配置 |
| `patch_start_script` | 修正启动脚本 |
| `start_server` | 启动后台服务端 |
| `stop_server` | 停止后台服务端 |
| `tail_server_logs` | 推送或读取日志输出 |

### 7.3 远程管理接口

| 接口 | 用途 |
|------|------|
| `ssh_connect` | 建立 SSH 连接 |
| `ssh_disconnect` | 断开 SSH 连接 |
| `remote_detect_paths` | 远程检测 DST 服务器路径 |
| `remote_run_mod_update` | 远程执行模组更新 |
| `remote_start_server` | 远程启动服务器 |
| `remote_stop_server` | 远程停止服务器 |
| `remote_tail_logs` | 远程流式读取日志 |

## 8. 约束与风险

### 8.1 约束

- 首版仅支持 Windows 本地场景。
- 后续版本需支持 macOS 图形界面应用和 Linux 远程管理。
- 前端必须维持 `Tauri + Vue + Vite + Reka UI` 方案。
- 当前 Python 模组更新逻辑是首版必须继承的兼容基线。
- 远程管理必须使用 SSH/SFTP 协议保证安全性。

### 8.2 风险

| 编号 | 风险 | 缓解措施 |
|------|------|----------|
| R-001 | 本机目录结构差异导致自动检测失败 | 始终提供手动修正入口 |
| R-002 | 启动脚本改写错误导致无法启动 | 写入前预览并保留回滚版本 |
| R-003 | `shadcn-vue` 缺少部分 block 模板 | 以官方组件族组合实现等价布局 |
