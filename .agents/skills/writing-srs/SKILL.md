# Writing SRS — 软件需求规格说明书编写技能

## 工作模式选择

收到请求后，**首先判断工作模式**：

| 用户输入特征 | 选择模式 |
|-------------|----------|
| 提供了充分的项目描述（功能、用户、约束等） | **快速生成模式** |
| 仅给出项目名称或一句话描述 | **交互引导模式** |
| 明确要求"直接生成" | **快速生成模式** |
| 明确要求"引导我填" / "一步步来" | **交互引导模式** |
| 不确定时 | 询问用户偏好 |

---

## 快速生成模式

**步骤**:

1. **解析输入** — 从用户描述中提取：系统名称、核心功能、用户角色、技术约束
2. **填充模板** — 使用 `templates/srs-ieee-29148.md` 生成文档，对未知字段使用 `{待填写}` 占位
3. **质检** — 确保关键需求有量化指标，P0 需求有验收标准（参见 `references/quality-standards.md`）
4. **输出** — 输出完整 Markdown 文档，文末附"建议评审重点"

**文档顶部说明（若有占位符）**:
```
> ⚠️ 以下字段需补充确认：{字段列表}
```

---

## 交互引导模式

分 3 轮对话，每轮最多 3 问：

**第 1 轮 — 项目全貌**
- 系统核心目标和要解决的业务问题
- 主要用户类型和他们的核心诉求

**第 2 轮 — 功能范围与质量要求**
- MVP 必须包含的功能 vs. 后续版本的功能
- 性能、可用性、安全合规的关键指标

**第 3 轮 — 约束与确认**
- 技术栈、时间、预算约束
- 确认理解，生成文档

详细访谈问题库见 `references/workflow-guide.md`。

## 文档结构（IEEE 29148-2018）

按以下章节顺序生成，完整模板见 `templates/srs-ieee-29148.md`：

1. **引言** — 目的、范围、术语、参考资料
2. **总体描述** — 产品视角、功能概述、用户类别、运行环境、设计约束、假设与依赖
3. **功能需求** — 按模块编号（FR-XXX），每条含优先级、前后置条件、主成功场景、异常场景、验收标准
4. **非功能需求** — 性能、安全、可用性、可维护性、可扩展性、合规性（全部量化）
5. **用户故事与用例** — 用户故事表格（US-XXX）+ 核心用例详述（UC-XXX）
6. **数据需求与数据字典** — 实体关系概览、字段详表、数据保留策略
7. **接口需求** — UI 需求、API 规范（方法/路径/认证/响应格式）、外部系统接口
8. **系统约束与假设** — 业务约束、技术约束、假设条件、风险矩阵
9. **验收标准** — 功能验收表、NFR 验收方法、发布 DoD 检查清单
10. **附录** — 需求优先级矩阵、溯源矩阵、开放问题、变更记录

## 需求编写规则

- **功能需求**: 使用"系统**必须**/应该/可以 + 动词"格式，禁用模糊词（快速/简单/友好）
- **非功能需求**: 全部量化，包含基准条件和测试方法
- **编号**: `FR-{模块}-{序号}`，`NFR-{类别}-{序号}`，`US-{序号}`，`UC-{序号}`
- **优先级**: P0（MVP 必须）/ P1（重要）/ P2（期望）/ P3（可选）

质量规范详见 `references/quality-standards.md`。

---

## 输出规范

- **格式**: 标准 Markdown，兼容 GitHub / Confluence / 飞书
- **语言**: 全程中文
- **文件名**: `SRS_{项目代号}_{版本}_{日期}.md`（如 `SRS_ECOMM_v0.1_20240101.md`）
- **版本**: 从 `v0.1` 草稿开始
- **占位符**: 未确定内容统一用 `{花括号}` 标注

生成完成后，在文档末尾输出：
```
---
📋 **建议评审重点**：
1. [章节] {关键待确认决策}
2. [章节] {需与干系人对齐的内容}
❓ **开放问题**：{列出文档内 Q-XXX 清单}
```
