# 文档类型定义与更新规则

本文件定义 spec-doc-sync 技能所管理的各类文档的结构要点和同步时的更新规则。

## 1. 需求规格文档（PRD/SRS）

### 典型路径
`docs/requirements/`, `docs/specs/`, `docs/prd/`

### 关键结构元素
- 功能需求条目（FR-*）
- 非功能需求条目（NFR-*）
- 验收标准（AC-*）
- 系统边界与范围
- 用户故事/场景

### 同步更新要点
- **代码变更触发**：通常不需要反向更新需求文档，除非代码变更反映了需求理解的修正
- **需求变更触发**：这是需求文档自身的变更，作为源头文档更新其编号和内容
- 更新时保持编号连续性，新增条目使用下一个可用编号
- 删除的需求标记为 `[已移除]`，不删除编号以保持可追溯性

---

## 2. 技术设计文档

### 典型路径
`docs/design/`, `docs/technical/`, `docs/architecture/`

### 关键结构元素
- 设计目标与非目标
- 架构概览
- 设计映射（DM-FR-* 映射到 FR-*）
- 详细设计（模块、接口、数据流）
- 技术选型与 ADR 引用

### 同步更新要点
- **接口变更**：更新详细设计中对应模块的接口描述（参数、返回值、异常）
- **架构变更**：更新架构概览图和模块关系
- **新增功能**：新增 DM-FR-* 映射条目
- **删除功能**：将对应 DM 映射标记为 deprecated
- 保持 DM 编号与 FR 编号的一一对应关系

---

## 3. API 契约文档

### 典型路径
`docs/api/`, `docs/contracts/`, 或项目根目录的 `openapi.yaml`/`swagger.json`

### 关键结构元素
- 端点定义（路径、方法）
- 请求/响应 Schema
- 参数定义（路径参数、查询参数、请求体）
- 状态码与错误响应
- 认证方式
- 版本信息

### 同步更新要点
- **端点变更**：精确更新路径、方法、参数定义
- **Schema 变更**：更新请求/响应的 JSON Schema 或类型定义
- **新增端点**：在合适的分组/标签下添加新端点定义
- **删除端点**：标记为 deprecated，保留定义但添加弃用说明
- OpenAPI/AsyncAPI 格式的文件需要保持格式有效性（YAML/JSON 语法正确）
- 更新版本号（如适用）

---

## 4. 测试规格文档

### 典型路径
`docs/test/`, `docs/test-specs/`, `docs/qa/`

### 关键结构元素
- 测试用例编号（TC-*）
- 测试类型（单元/集成/E2E）
- 前置条件
- 测试步骤
- 预期结果
- 测试数据
- 覆盖矩阵（TC ↔ FR 映射）

### 同步更新要点
- **接口变更**：更新受影响测试用例的步骤和预期结果
- **新增功能**：新增测试用例，编号递增，并更新覆盖矩阵
- **行为变更**：更新预期结果，可能需要新增边界条件测试
- **删除功能**：将对应测试用例标记为 `[SKIP: 对应功能已移除]`
- 保持 TC 与 FR 的覆盖映射完整

---

## 5. CodeGuide 设计文档

### 典型路径
`docs/code-guide/`, `docs/codeguide/`, 或由 `CODE_GUIDE_INDEX.md` 索引

### 关键结构元素
- 函数/类级别的设计说明
- 输入/输出描述
- 调用链与依赖关系
- 状态变化
- 设计意图与约束

### 同步更新要点
- **函数签名变更**：更新输入/输出描述
- **调用链变更**：更新依赖关系图
- **新增函数/类**：如果已有 CodeGuide 体系，提示用户生成新文档（本技能不初创）
- **删除函数/类**：标记对应文档为 deprecated，更新索引
- **内部重构**：更新实现细节但保持外部描述不变
- 如果存在 `CODE_GUIDE_INDEX.md`，同步更新索引
