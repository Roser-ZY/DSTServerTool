# Verifying Implementation

## 前置准备

1. 确认 `docs/<topic>/` 目录下存在以下文档（统称"文档"）：
   - **design 文档**：架构/设计方案
   - **plan 文档**：实现计划（任务列表）
   - **FR 文档**：功能需求

2. 确认待审查的 git 提交范围（commit hash 或 branch）。

3. 如果当前使用了 `using-git-worktrees` 技能，以该技能指定的 worktree 和 branch 为主。

4. 激活 `interface-roadmap` 技能（如有），用于后续接口验证。

## 审查流程

### Step 1：读取并分析文档

读取所有文档，提取以下信息：
- **功能点列表**：FR 文档中所有需求功能
- **设计方案**：design 文档中的架构、模块划分、数据结构
- **实现计划**：plan 文档中的任务项及预期实现方式
- **预期接口/类/函数**：文档中明确提及的接口、类、函数、文件

### Step 2：获取代码变更

```bash
# 查看 git 提交的变更文件列表
git diff <base-commit> HEAD --name-only

# 查看具体变更内容
git diff <base-commit> HEAD
```

### Step 3：调用 requesting-code-review 技能

使用 `requesting-code-review` 技能对变更代码进行标准代码质量审查（代码风格、逻辑正确性、潜在 bug 等）。

### Step 4：调用 interface-roadmap 技能（如有）

使用 `interface-roadmap` 技能查找代码实现中涉及的接口、文件、类的定义，确认：
- 实现中使用的接口是否存在且定义正确
- 使用方式是否符合接口规范

### Step 5：一致性审查

**5.1 实现与文档的一致性**

逐条对比文档内容与代码实现：
- 如发现实现与文档不符，先理解代码的实现思路
- 判断该偏差是否合理（技术原因、优化等）
- 如不确定是否合理，**立即向用户提问**，不得自行假设

**5.2 功能完整性审查**

检查文档中每个功能点是否均已实现：
- 列出所有已实现的功能点 ✅
- 列出所有**遗漏**的功能点 ❌

如发现遗漏：
1. 明确指出遗漏的功能点
2. 调用 `executing-plans` 技能对遗漏内容进行补充实现
3. 实现完成后，**重新调用 `verifying-implementation` 技能**，从头验证

**5.3 多余功能审查**

检查代码实现中是否存在文档**未提及**的功能：
- 列出所有多余功能
- **等待用户指示**后，再决定删除或保留，不得自行处理

**5.4 未知接口审查（重点）**

重点检查代码中使用的接口、函数、类，与文档中提及的进行对比：
- 找出文档中**未出现**的接口/函数/类
- 使用 `interface-roadmap` 技能（如有）查找这些接口的实际定义
- 判断：
  - 接口**未实现**：立即指出，并使用正确接口替换或补充实现
  - 接口**使用错误**：立即指出错误用法，并修正为正确调用方式
  - 接口**合理存在**（标准库、通用工具等）：记录但不阻断

### Step 6：审查结果汇总

输出审查报告，包含：

```
## 验证结果

### ✅ 已满足的功能点
- [功能点列表]

### ❌ 遗漏的功能点
- [遗漏列表，无则填"无"]

### ⚠️ 多余功能（待用户确认）
- [多余功能列表，无则填"无"]

### 🔍 文档未提及的接口/类/函数
- [接口列表及处理结果，无则填"无"]

### 📋 代码一致性问题
- [与文档不符的问题列表，无则填"无"]
```

## 完成条件

技能执行完成后，必须保证：

- [ ] 代码实现**完全满足**文档中所有功能点
- [ ] 代码实现**严格遵循** interface-roadmap 技能（如有）中定义的接口
- [ ] 不存在**臆想接口**（未定义即使用的接口）
- [ ] 不存在**未实现功能**（文档要求但未实现的功能）
- [ ] 多余功能已经**用户确认**处理方式

## 最终提交

审查通过后，在指定的 worktree 和 branch 中提交：

```bash
# 如使用 using-git-worktrees 技能，切换至对应 worktree
cd <worktree-path>

# 提交验证通过的实现
git add .
git commit -m "verify: implementation verified against docs/<topic>/ documents"
```

如果在审查过程中有补充修改，提交信息应描述修复内容：

```bash
git commit -m "fix: supplement missing features per docs/<topic>/ requirements"
```
