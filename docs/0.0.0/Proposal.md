# 0.0.0 提案

## 版本定位

`0.0.0` 是 DSTServerTool 的首个可运行提案版本，目标不是覆盖完整服务器生命周期，而是先把“本地路径确认 -> 模组同步 -> 默认存档准备 -> Token 配置 -> 服务端启动与日志查看”这一条最短闭环做通。

该版本完成后，用户应能在 Windows 本机上通过图形界面完成基础服务器准备，并具备最基本的运行与排障能力。

## 版本目标

- [ ] 自动检测 DST 安装目录和 DST Server 安装目录。
- [ ] Mod 自动更新。
- [ ] 默认存档创建与复制。
- [ ] Token 配置教程与启动脚本修改。
- [ ] DST Server 基本后台启动与日志输出。
- [ ] 上述所有能力均提供对应 UI 界面。

## Feature 划分

### Feature 01 环境检测与路径确认

**目标**  
降低首次使用时的目录确认成本，优先自动发现本机已有安装目录。

**范围**
- 自动检测 Steam 根目录。
- 自动检测 DST 游戏目录。
- 自动检测 DST Dedicated Server 目录。
- 检测失败时允许用户手动修正。
- 保存已确认路径，供后续 Feature 复用。

**交付界面**
- 初始化页面
- 路径检测结果卡片
- 手动修正表单

### Feature 02 模组自动更新

**目标**  
把已存在的 Python 模组更新能力产品化为桌面 UI 操作流。

**范围**
- 扫描服务器 `mods` 目录中的 `workshop-*` 模组。
- 从 Workshop 目录和游戏目录匹配来源模组。
- 按更新时间决定是否更新。
- 展示逐项结果与摘要统计。

**交付界面**
- 模组更新页面
- 更新结果列表
- 更新摘要区域

### Feature 03 默认存档创建与复制

**目标**  
让用户在没有复杂配置前，先得到一个可启动的默认存档基线。

**范围**
- 创建默认 Cluster 目录结构。
- 将默认模板或已有基础存档复制到目标 Cluster。
- 校验目标路径是否可写。
- 展示创建或复制结果。

**交付界面**
- 存档初始化页面
- 默认存档创建对话区
- 执行结果提示

### Feature 04 Token 配置指导与启动脚本修改

**目标**  
减少用户手工查文档与改脚本的成本。

**范围**
- 展示 Token 获取与填写指引。
- 校验 Token 是否已输入。
- 将 Token 写入指定配置文件或启动脚本所需位置。
- 对启动脚本进行必要的参数补齐或修正。

**交付界面**
- Token 配置页面
- 教程提示区
- 启动脚本预览/确认区

### Feature 05 服务端后台启动与日志输出

**目标**  
让用户在桌面端完成最基础的启动、观察与失败定位。

**范围**
- 以后台任务方式启动 DST Dedicated Server。
- 展示启动中、运行中、失败、结束状态。
- 实时输出标准输出与标准错误日志。
- 支持基础停止操作。

**交付界面**
- 服务端运行页面
- 日志输出面板
- 运行状态栏

## 不纳入 0.0.0 的范围

- 基于文章的完整分步搭建向导。
- 多配置档切换。
- 存档备份与恢复。
- 远程服务器管理。
- 更复杂的运维任务编排。

## 版本验收口径

`0.0.0` 应满足以下条件：

1. 用户首次打开应用后，可确认或修正 DST / DST Dedicated Server 路径。
2. 用户可通过 UI 执行一次模组更新并看到明确结果。
3. 用户可创建或复制默认存档。
4. 用户可完成 Token 配置，并让启动脚本进入可运行状态。
5. 用户可在 UI 中启动服务端并看到连续日志输出。

## 对 SRS 的要求

- SRS 需显式标注每项需求的目标版本。
- `0.0.0` 需求必须与以上 5 个 Feature 一一对应。
- 非 `0.0.0` 的需求应下沉到后续版本，不再与首版目标混写。
